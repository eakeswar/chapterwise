## 1. Executive summary

Chapterwise converts a school textbook PDF into a **document-order topic tree** (chapter → section → subsection). Each topic shows a grounded explanation, source pages, diagrams/photos, **topic-scoped Q&A**, and **text-to-speech**. Unlike a magazine-style layout product, topics stay hierarchical and follow the book, not font size or page design.

The work was delivered in **numbered product steps**, with a test-and-approve loop after each major piece: extract → topic tree → UI → explanations → Q&A → TTS → image handling → polish.

Over six weeks the application moved from an empty monorepo to a working end-to-end system that can ingest the **NCERT Class 9 Science textbook (≈301 MB, 1,299 pages)** locally, build **≈223 topics in under a second** (regex path), stream explanations and answers, classify and enhance images, and narrate with a selectable Azure TTS voice.

## 2. Approach

### 2.1 Product constraints

- **Local-first extraction.** Do not send the full PDF to a cloud model for parsing in v1. Use PyMuPDF and OCR on CPU; use LLMs only for language tasks (tree, explanation, Q&A).
- **Ordered hierarchy.** The tree must follow textbook headings, not visual layout.
- **Grounded generation.** Explanations and answers must stay inside the open topic’s source; if the section does not contain the answer, the model must say so.
- **Cost and safety for images.** Formulae and labelled diagrams must never be regenerated by an image model. Decorative photos may be enhanced **on demand** only.
- **Fail soft.** A dead tunnel or Azure error must not freeze the UI; show source text and a clear status.

### 2.2 Engineering method

1. Follow a published **eight-step build order** (upload/extract → topics → frontend tree → topic view → ask → TTS → image enhance → polish).
2. **Implement one step, then test** (often on pages 1–8, then on harder pages, then the full book).
3. **Measure before changing** (extract timing phases, GPU OOM logs, Cloudflare 502/524, classification scores).
4. Prefer a **simple reliable path** when a fancy path is unstable (regex TOC vs Llama-1B JSON tree).
5. Keep a living project log (`.cursorrules` changelog) so the next session starts from facts, not memory.

### 2.3 Architecture (as shipped)

## 3. Challenges, root causes, and solutions

| Challenge | What went wrong | How it was solved |
|-----------|-----------------|-------------------|
| **300 MB textbooks felt “stuck” on upload** | The API waited for **full extraction of every page**, not just the HTTP upload. Header/footer analysis originally scanned **all 1,299 pages** even for a 1–10 page test (~93 s of ~99 s). | Page-range extract (`page_start` / `page_end`); sample **36 pages** for headers and cache by file fingerprint; parallel workers; later defer image base64. Partial extract dropped to **~6–8 s**. |
| **Kaggle + Cloudflare timeouts (502 / 524 / SSL EOF)** | Sync `/upload_and_extract` and `/chat/completions` exceeded free-tunnel limits (~100 s). | Chunked 4 MB upload; async extract/chat + poll; treat 502/503/524 as tunnel blips; **409 + job_id** when busy; fail fast if DNS is dead so `/topic` still returns source. |
| **Azure `DeploymentNotFound` for chat** | TTS (`gpt-4o-mini-tts`) and images (`gpt-image-2`) worked; **chat was never deployed** on that resource. Keys and URLs were mixed. | Split clients: `AZURE_CHAT_*` vs TTS/image keys. Later a **student Azure chat resource** (`gpt-4.1-mini`) became the default `TEXT_PROVIDER`. |
| **Llama 1B as topic builder** | Malformed JSON, copied few-shot titles, invented subsections, **CUDA OOM** (~13 GB attention spike), hangs on ~12k-char prompts. | JSON repair + retry; tighter prompts; `repetition_penalty` / `no_repeat_ngram_size`; token caps; **regex heading TOC as default** (full book: 223 topics / **0.16 s**). LLM path kept behind a flag. |
| **Gated Hugging Face + Kaggle secrets** | 401 on Llama: missing `HF_TOKEN` secret vs token present but no model access vs mismatched `KAGGLE_API_SECRET`. | Load secrets via Kaggle User Secrets; print **present/length only**; `huggingface_hub.login`; accept the gated model licence. |
| **Dead Kaggle blocked opening a topic** | Client retried connection errors until a **600 s** LLM timeout. | After inner retries, raise **unreachable immediately**; UI shows `explanation_status=failed` with source (~3 s). |
| **Full-book extract memory/time** | Eager base64 of every image; RapidOCR constructed **once per worker thread**. First full run **~287 s**, peak **~2.4 GB**. | Default **defer image encoding**; single RapidOCR under a lock. Later full run **~209 s**. `/topic` encodes only that topic’s xrefs. |
| **Black gallery images** | 1-bit ICC Gray + **SMask**: raw PNG looked solid black (art lived in the mask). | Pixmap decode to RGB PNG; mask as alpha; empty color+mask → transparent PNG. |
| **HD generate invented scenes** | Vision + `images.generate` plus **chapter explanation** in the prompt turned wheat grains into a farm. Colour diagrams (xylem/phloem) were labelled **decorative** because PDF text overlap was 0. | On-demand **Generate HD** only; **caption-primary** prompts; then **`images.edit`** with source bytes and `input_fidelity=high`. RapidOCR **on the crop**: baked labels → informational (Lanczos only). Classify in background so `/topic` stays fast. |
| **Streaming vs classify poll** | Polling `/topic` every 3 s returned `explanation: null` and **wiped** in-progress SSE text. | `mergeTopicPoll`: keep streaming text; cache explanation only on SSE `done`. |
| **False `Chapter N` headings** | Prose such as “see Chapter 7” became extra chapter nodes (dozens of duplicates / out of order). | Tighten chapter regex to **start-of-line** headings. Layout/OCR reading order remains a known limit; DocLayout-YOLO was **investigated**, not adopted as default. |

## 4. Improvements delivered (product and engineering)

**Performance**

- Header/footer sampling + fingerprint cache.
- Parallel extract (thread pool on Windows).
- Deferred image base64; on-demand encode + in-memory cache.
- Regex TOC: full book in **0.16 s** vs multi-minute / failing Llama tree.

**Reliability**

- Async Kaggle jobs, retries, chat watchdog, `/chat/reset`.
- Split Azure credentials; `/debug/text` and `/debug/azure`.
- Fail-soft explanations, Q&A, and HD generate.

**Correctness**

- Body text is **not dropped**: each heading’s page range runs until the next heading.
- Fallback chapter `Pages {start}–{end}` if a range has no headings.
- Q&A grounded in explanation + source of **that topic only**.
- Informational vs decorative routing; OCR gate for painted labels.
- `images.edit` keeps identity of photos (costume, grain pile) instead of inventing a new scene.

**UX**

- Animated upload screen with elapsed time and extract/build timings.
- Sidebar inner-scroll; source card **collapsed by default**.
- Markdown when complete; cursor while streaming.
- Ask: FAB + overlay drawer with a chat thread.
- TTS voice picker (10 confirmed voices), default **shimmer**, persists across topic switches.
